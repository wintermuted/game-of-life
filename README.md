This project is an implementation of [Conway's Game of Life](https://en.wikipedia.org/wiki/Conway%27s_Game_of_Life) written in [Typescript](https://www.typescriptlang.org/).

The size badges are regenerated by CI on each production deployment. They total all
built JavaScript and CSS assets, including optional chunks, but exclude source maps,
HTML, images, and other static files. Gzip is calculated per file using Node's default
compression settings; actual server compression may differ. Sizes use decimal KB/MB.
PR previews publish their own badges without changing these production totals.

The coverage badge reports aggregate line coverage across all eight packages from
the production revision's unit tests, including untested source files. Test files,
test setup, type declarations, and the Storybook catalog are excluded. CI runs
the existing workspace test configurations together with V8 coverage and publishes
the badge alongside the app only after tests pass. Run `npm run test:coverage` to reproduce the report.
PR preview coverage badges remain isolated from the production badge.

## Goals

- Provide a succinct example of my programming skill in TypeScript vis-a-vis a known programming problem.
- Demonstrate my understanding of [Big O notation](https://en.wikipedia.org/wiki/Big_O_notation).
- Provide myself an opportunity to learn HTML5 Canvas.

## Current State

- The rules of the Game of Life have been implemented.
  - A Dictionary is used as the primary datastructure.
  - The implementation of the core logic can be found in [`packages/core/src/core/game.ts`](https://github.com/wintermuted/game-of-life/blob/master/packages/core/src/core/game.ts).
  - A class [`Game`](https://github.com/wintermuted/game-of-life/blob/master/packages/core/src/class/Game.ts) can be used to start a game and step through it.
- The game rules are backed with unit tests.
- The game has been tested with common Still Life & Oscillator patterns.
- A rudimentary UI built with React has been added, however it is poorly optimized. A rewrite is necessary for it to be performant with larger grids.

## Architecture

This project is organized as an **NX monorepo** with npm workspaces:

### Canonical App Path

- The canonical application is `packages/app/src/`.
- Reusable React components live in `packages/ui*`; these are libraries, not apps.
- The historical top-level `src/` tree has been removed.
- Use root scripts (`npm run dev`, `npm run build`, `npm test`) or Nx targets rather than the deprecated root Vite entry.

### Packages

- **`@game-of-life/core`** (`packages/core/`) - Core game logic library
  - Pure TypeScript implementation of Conway's Game of Life rules
  - Game state management (Grid class)
  - Pattern definitions (oscillators, still lifes, spaceships, methuselahs)
  - Type definitions and interfaces
  - No dependencies on UI frameworks

- **`@game-of-life/app`** (`packages/app/`) - React application
  - Vite-based React application
  - Owns startup, routes/pages, assets, translations, persisted theme preferences, and simulation orchestration
  - Loads the Wintermuted theme stylesheet
  - Imports UI libraries directly and composes them with API/util/core

- **`@game-of-life/ui`** (`packages/ui/`) - Shared primitives and theme support
  - Tabs, segmented controls, language/palette selectors, and palette types/constants
  - Controlled `ThemeModeProvider` and its shared context
  - Receives theme state and translation initialization from the host app; no startup, routes, assets, API calls, or preference persistence
  - No game-engine or feature-package dependencies; React/translation frameworks are peers
  - Does not re-export feature components or a stylesheet

- **`@game-of-life/ui-grid`** (`packages/ui-grid/`) - Grid rendering
  - `Grid`, `CanvasGrid`, `GridSquares`, and cell-color rendering helpers
  - Owns grid CSS, exported as `@game-of-life/ui-grid/style.css`
  - Depends on UI primitives/theme, core, and util; no controls dependency

- **`@game-of-life/ui-patterns`** (`packages/ui-patterns/`) - Pattern components
  - Pattern preview, selector, standard/custom input components
  - Depends on UI primitives/theme and core, not grid or controls

- **`@game-of-life/ui-controls`** (`packages/ui-controls/`) - Game controls
  - `GridControls` and `RulesPanel`
  - Depends on ui-patterns previews, UI primitives/theme, and core
  - Tested through app's translated-component integration tests

- **`@game-of-life/api`** (`packages/api/`) - Client-side data services
  - Browser-backed boards, template names, recents, favorites, forks, and profile
  - Local/session storage selection and data migration
  - Preserves existing storage keys and synchronous service APIs; no HTTP server
  - Depends on `@game-of-life/util` and `@game-of-life/core`

- **`@game-of-life/util`** (`packages/util/`) - Shared helpers
  - Grid encoding/decoding and URL state
  - Coordinate/viewport translation, generation speed, and relative-time formatting
  - Depends only on `@game-of-life/core` and Lodash; no React or theme dependencies

- **`@game-of-life/storybook`** (`packages/storybook/`) - Product component catalog
  - Storybook with React/Vite, generated component documentation, controls, and accessibility inspection
  - Imports product components through their owning UI package exports; does not duplicate upstream primitives
  - Hosts the existing theme, grid CSS, and app styles/translations without mounting the app or its persistence
  - Standalone development server and static output; no changes to the app entry point

App, base ui, and ui-controls consume the nine generic components from the published
`@wintermuted/ui-react` package (1.1.0 or later), styled by `@wintermuted/ui-theme`
(1.0.2 or later). Toggle groups, facets, sortable headers, stat cards, ranked bars,
toasts, color pickers, number steppers, and language selectors are owned upstream;
their translations, palette/default mapping, color drafts, routing, persistence,
and notification timing stay in local adapters. App loads the theme stylesheet
once; there is no separate staging package or stylesheet. Diagnostics explicitly
use compact stat cards. Existing local Tabs, Dialog, Menu, and Tooltip are unchanged.

Import components, shared functions, and types through their owning package's
public entry point, not through a UI umbrella. App imports all four UI libraries;
feature libraries depend on base UI, and controls additionally depend on patterns.
Libraries must not import app; UI libraries must not import API.
Feature bundles externalize sibling libraries so all components share one theme
context. App tests exercise translated components through their public exports,
while standalone library tests do not import app's translation configuration.

### TypeScript Composite Builds

The project uses TypeScript's [project references](https://www.typescriptlang.org/docs/handbook/project-references.html) for incremental builds:

- Root `tsconfig.json` references core, util, API, and the four UI libraries
- Library configurations use `composite: true` and emit JavaScript and declarations to `dist/`
- Libraries declare TypeScript project references to their library dependencies
- UI libraries emit declarations with TypeScript and ES modules with Vite; ui-grid emits a stylesheet
- App uses `noEmit` and source aliases for workspace imports, then bundles with Vite
- Vite/Vitest resolve workspace libraries from source in development and tests;
  direct tests do not require prebuilt libraries

This enables:

- Faster incremental builds
- Better IDE performance
- Clear dependency boundaries between packages

## Development

### Prerequisites

Use Node.js 24 LTS (24.15.0 or newer). Node 22.22.2 or newer is also
supported and tested in CI. The root `.nvmrc` selects Node 24.
Node type definitions intentionally track Node 24 rather than Node 26.
TypeScript is held at 6.0.3 because Nx 24 dependency discovery still requires
the compiler API removed in TypeScript 7 (`readConfigFile`).
All dependencies, including the published Wintermuted theme, install from npm;
no sibling theme checkout is required.

```bash
npm ci
```

CI runs clean installation, Oxlint, Oxfmt checks, package builds/typechecks,
and all workspace tests on Node 22 and 24. Local lint, typecheck, and build runs
are not required for this workflow; CI owns those validation gates.

### Product component library

Run `npm run storybook` to maintain and inspect reusable product UI independently
of the game. Stories currently cover segmented controls, tabs, palette selection,
pattern previews, the canvas grid, and the rules panel, including empty, disabled,
locked, editable, and dark variants. The toolbar switches between light/dark themes
and English/Spanish. The preview uses dedicated per-language i18next instances with
the app's resources, so translated variants can coexist on a Docs page without
changing other stories. It uses no browser language detection or persisted preferences.

Stories live in `packages/storybook/src/*.stories.tsx`. Import components from
their owning `@game-of-life/ui*` public entry points and use real engine fixtures
from `@game-of-life/core`. Keep production components in their existing libraries;
Storybook is a host, not a new component implementation or UI umbrella.
Add a typed `Meta` with `satisfies Meta<typeof Component>` and `StoryObj<typeof meta>`,
provide representative args, and describe meaningful states. Controlled components
use `useArgs` so interactions also update the Controls panel. Global `autodocs`
creates API documentation; `play` functions demonstrate interaction assertions
using `storybook/test`. Those assertions run when their stories open in Storybook;
CI currently validates the static build, not browser interaction tests.

The Accessibility panel runs automated checks for the selected story. Treat
results as review evidence, not a replacement for keyboard and screen-reader
checks, particularly for canvas components. Product-specific layout CSS still
lives in the app and is loaded by the preview rather than copied into the catalog.

`npm run build:storybook` produces `packages/storybook/build` for any static host.
The existing `npm run build` CI gate includes the catalog and its TypeScript
configuration on Node 22 and 24. The Node 24 job uploads a
`product-component-library` artifact; this setup does not publish another website
or change production/PR app deployments. Development resolves libraries from
source and does not require prebuilding them.

Oxlint uses the shared `.oxlintrc.json` from every package/Nx lint entry point.
It preserves the existing recommended JavaScript/TypeScript rule intent,
React Hooks checks, refresh export checks, underscore-unused exemptions, and
test-only explicit-any exceptions. Oxlint's core rules cover the former
TypeScript-specific array-constructor, loss-of-precision, and unused-variable
rules. The former duplicate-argument, octal-literal, and `new Symbol` checks
are covered by parser/compiler diagnostics rather than standalone Oxlint rules;
extra semicolons and mixed indentation are handled by Oxfmt.
Oxfmt preserves single-quoted code, uses two-space indentation and LF endings,
and excludes generated outputs and the npm-generated lockfile.

### File size and responsibility boundaries

Keep authored source files at **500 total lines or fewer**, counting blank lines
and comments. Prefer cohesive components, domain hooks, and pure helpers over
large pages or controller hooks. Do not compress formatting or move a monolith
into another file to meet the limit. Tests follow the same guideline.

Oxlint's `max-lines` rule enforces this for JavaScript/TypeScript across all nine
packages in CI. Existing zero-warning gates remain in place. CSS/SCSS, JSON, and
YAML are not checked by Oxlint; their size guideline is review-enforced.

The shared `.oxlintrc.json` has no file-size exceptions. Grid orchestration,
minimap geometry and controls, and canvas drawing have separate responsibilities.
The profile board gallery is a separate view, and each locale composes its
play-page dictionaries from a sibling module without changing translation keys.
Do not add directory-wide exemptions or inline suppressions.

The existing `packages/app/src/app/styles/App.css` (4,124 lines) is a deferred,
review-enforced stylesheet exception. It is not covered by the Oxlint rule.
There is no blanket data/test exemption, and `max-lines-per-function` is not
enabled: function-length policy is separate from file-length policy.

### GitHub Copilot App

Review and accept `.github/github-app.yml` in the app to enable its scripts.
**Setup** runs automatically when a session is created and can also be run
manually. It requires a supported Node.js version and npm, and runs `npm ci`
at the workspace root to install all workspace dependencies, including the
published `@wintermuted/ui-theme` package.

**Run** starts the local Vite development server using `npm run dev`. The app
detects Vite's local URL (including the `/game-of-life/` base path) and opens it
in the integrated browser.

## Deployment

This project is automatically deployed to GitHub Pages using GitHub Actions:

- **Production Deployment**: Automatically deployed to GitHub Pages when changes are merged to the `main` or `master` branch.
  - 🌐 **Live Site**: https://wintermuted.github.io/game-of-life/
- **PR Previews**: Each pull request receives a preview deployment which is automatically cleaned up when the PR is closed. The preview URL is posted as a comment on the PR.

The deployment workflows are located in `.github/workflows/`:

- `deploy-pages.yml` - Main production deployment
- `deploy-pr-preview.yml` - PR preview deployments
- `cleanup-pr-preview.yml` - PR preview cleanup
